## Demo: Trigrep CLI across a working set
##
## Two search narrowing progressions with different recipe destinations:
##  1. Item: search recipe (FindTypes) for FQN-precise inventory
##  2. RestTemplate: transformation recipe for migration to RestClient
##
## (A brief struct interlude in between shows code-shape matching as a capability.)

# Move into the working set so `mod search .` covers the whole portfolio.
cd working-set

# Show what's actually in the working set (the repos we'll search across).
mod list .

## CLEAR
## ── Section 1: Item climb → FindTypes (search recipe) ──────────────────────
## Premise: "What Item types do we have across services? FQN-precise inventory."
## Climb: literal → type:symbol → \bItem\b regex → recipe.
## Ordering note: type:symbol Item still includes *Item* substring matches
## (ItemRepository etc.), so the \bItem\b regex is the narrowest text-based step.
## Recipe (FindTypes) is FQN-precise, so it narrows to one specific Item type.

# Broad. Every textual "Item" (the Item classes + ItemRepository + comments + string literals).
mod search . Item

# Symbol. Narrower than literal but still catches *Item* substrings (ItemRepository, ItemController).
mod search . type:symbol Item

# Word boundary. Narrowest text-based: only "Item" as a standalone word.
mod search . '/\bItem\b/'

# Hand to FindTypes. FQN-precise (ewolff catalog's Item here).
mod run . --last-search --recipe=org.openrewrite.java.search.FindTypes -PfullyQualifiedTypeName=com.ewolff.microservice.catalog.Item

## CLEAR
## ── Interlude: Struct + LST-filter showcase ────────────────────────────────
## Queries not tied to either climb. Two flavors:
##   - Struct: code-shape matching with holes that capture varying content.
##   - LST filters: semantic queries grep can't ask (extends:, throws:, visibility:, ...).

# Throw-new statements. Match the shape (not the type). :[exception:id] captures different exception types; :[args:e] captures varying message shapes (empty, msg-only, msg + cause).
mod search . 'struct:throw new :[exception:id](:[args:e])'

# Annotations with parameters. :[ann:id] captures the annotation name (@RequestMapping, @PreAuthorize, @Qualifier, @Cacheable, ...); :[value] captures whatever's inside the parens.
mod search . 'struct:@:[ann:id](":[value]")'

# Inheritance filter. Every class that directly extends RuntimeException. grep can't ask "extends" semantically.
mod search . extends:RuntimeException

# Composed filter. Every public method that declares throws IOException. Two LST filters working together.
mod search . visibility:public throws:IOException

## CLEAR
## ── Section 2: javax → jakarta climb → migration recipe (transformation) ───
## Premise: "Modernize for Spring 6 / Boot 3 — javax.* imports become jakarta.*."
## Climb: literal → narrow to .java only → migration recipe.
## The handoff goes to a transformation recipe this time, not a search recipe.
## --last-search scopes to the 3 of 4 repos still on javax (ewolff, mall, piggymetrics);
## petclinic-microservices (already migrated to jakarta) is silently skipped —
## that's the visible narrowing payoff over running the recipe unscoped.

# Broadest. Every textual "javax" — Java source, pom.xml/build.gradle deps, comments.
mod search . javax

# Narrow to .java only. Drops build-file matches.
mod search . javax file:java

# Hand to the migration recipe. --last-search scopes to repos that have javax (3 of 4).
mod run . --last-search --recipe=org.openrewrite.java.migrate.jakarta.JavaxMigrationToJakarta
